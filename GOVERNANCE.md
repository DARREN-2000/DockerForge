# Governance

## Project Roles

### Users

Users are community members who have a need for the project. They are the most important members of the community and without them the project would have no purpose. Anyone can be a user; there are no special requirements.

### Contributors

Contributors are community members who contribute in concrete ways to the project. Anyone can become a contributor, and contributions can take many forms, including code, documentation, bug reports, and community support.

### Maintainers

Maintainers are first and foremost contributors that have shown they are committed to the long-term success of a project. Maintainers have push access to the project repository.

## Becoming a Maintainer

Maintainers are expected to review pull requests, triage issues, and guide the technical direction of the project. To become a maintainer, you should:

1. Have a history of sustained contributions to the project (typically over several months).
2. Demonstrate a deep understanding of the project's architecture and goals.
3. Be nominated by an existing maintainer.
4. Receive a consensus vote from the current core maintainers.

## Decision Making

For everyday decisions, we employ a "lazy consensus" model. A maintainer will state their intended action and if no one objects within a reasonable timeframe (e.g., 72 hours), the action is taken.

For significant architectural changes or project-wide decisions, a formal proposal (e.g., via a GitHub Issue or Design Doc) should be created. These decisions require explicit consensus from the core maintainers.
